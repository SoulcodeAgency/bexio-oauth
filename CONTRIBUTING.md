# Contributing

Thanks for helping. The short version:

1. Read [docs/development.md](docs/development.md) for setup, tests and the CI/CD flow.
2. Open an issue first for anything bigger than a small fix, so we can agree on the approach.
3. Branch from `main`, keep the PR focused, and give it a [Conventional Commit](https://www.conventionalcommits.org/) title (`feat: …`, `fix: …`, `docs: …`). PRs are squash-merged; the title becomes the commit and drives the release.
4. Run `npm run check` before pushing. Behavior changes need tests and an update to [docs/integration.md](docs/integration.md).
